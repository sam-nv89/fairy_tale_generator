## 11.03.2026
### 🐛 Bug Fix: Google OAuth — «тихое» обновление без ошибок и входа (v4)
**Статус**: Выполнено

#### Причина:
Предыдущая попытка передавать `client_id` через `query_params: {state: client_id}` конфликтовала с внутренним использованием `state` в PKCE flow Supabase. OAuth state — это security механизм PKCE, его нельзя перезаписывать. В результате Supabase тихо отклонял запрос: не было ни входа, ни ошибки.

#### Правильное решение:
`client_id` теперь встраивается в `redirect_to` URL как `?auth_cid=<id>`:
- **`sign_in_with_google()`**: `redirect_to = f"{base_url}?auth_cid={client_id}"`  
- Supabase добавит `?code=XXX` к этому URL → финальный callback: `?auth_cid=abc&code=XXX`
- **`handle_oauth_callback()`**: читает `auth_cid` из query params → восстанавливает `client_id` в session_state → `get_supabase_client()` создаёт клиент с правильным `IsolatedDiskStorage` → `code_verifier` найден → `exchange_code_for_session()` успешен.

### 🐛 Bug Fix: Мерцание «Отрывок сказки» в карточках Hero-секции
**Статус**: Выполнено

#### Причина:
Карточки-сниппеты (`story-snippet`) рендерились Python-кодом с `{t("story_snippet_title")}` в заголовке. Так как `t()` вызывался единожды в контексте одного языка, все 8 карточек кратковременно отображали одинаковый русский текст. Через 200–600ms JS-скрипт `initTypingEffect()` перезаписывал заголовки правильными値 из `all_stories`.

#### Решение:
1. **`landing.py` → `render_hero()`**: Убран статический `{t("story_snippet_title")}` из `<span id="typing-title-{i}">`. Теперь span пустой при hydration — ни одна карточка не мерцает.
2. **`landing.py` → `render_scripts()`**: Логика вызова `initTypingEffect()` переработана с `pollCount === 0` на retry-цикл с проверкой `doc.getElementById('typing-title-0')`. Функция запускается сразу, как только DOM-элементы становятся доступны, а флаг `window.__typingInited` предотвращает повторный запуск.

## 26.02.2026 (чт, Update 50)
### 🔧 Refactor: Полная переработка селектора языков на лендинге
**Статус**: Выполнено

#### Постановка задачи
Селектор языков на лендинге отображался некорректно: белый фон baseui, "мерцание", непредсказуемое CSS-позиционирование поверх iframe.

#### Корневая причина
Архитектурная проблема: `st.selectbox` (нативный виджет Streamlit) рендерился в основном DOM-потоке, а навбар — в `st.html()` (изолированный iframe). CSS `position: fixed` + JS-хак через `MutationObserver` не могли надёжно очистить inline-стили baseui.

#### Решение
Полностью заменён подход:
- **Было**: `st.selectbox` + CSS `position: fixed` + JavaScript `setInterval()` / `MutationObserver` для очистки inline-стилей ≈ 120 строк хрупкого кода.
- **Стало**: Нативный HTML `<select>` непосредственно внутри навбара через `components.html()`. Обмен данных с Python — через `st.query_params` API.

Преимущества нового подхода:
1. Полный контроль над стилями (custom appearance, border-radius, hover/focus эффекты).
2. Нет зависимости от тайминга (исчезли `setInterval`, `MutationObserver`, `setTimeout`).
3. Нет CSS-хаков с `position: fixed` для Streamlit-виджета.
4. Навбар и селектор рендерятся как единый компонент — гарантированная консистентность.

#### Технические детали
- При выборе языка JS устанавливает query param `?lang=CODE` и перезагружает страницу.
- Python-сторона (`render_navbar`) считывает `st.query_params["lang"]`, обновляет `st.session_state.user_lang`, удаляет param и вызывает `st.rerun()`.

## 24.02.2026 (вт, Update 42)
### 🐛 Bug Fix: Закрытие списка жанров при прокрутке
**Статус**: Выполнено

#### Постановка задачи
Пользователь сообщил, что при попытке прокрутить выпадающий список `st.multiselect` / `st.selectbox` (выбор жанров) меню списка сразу же сбрасывается и закрывается.

#### Решение
Причиной проблемы было поведение кастомного JavaScript и CSS:
1. **Кастомный JavaScript (styles.py)**: В проекте внедрен JS-код `handleScroll()`, который принудительно закрывал открытые popover'ы при *любом* скроллинге (чтобы избежать "отрыва" выпадающих менюшек от инпутов при скролле главной страницы браузера). В скрипт было добавлено исключение: теперь, если скролл происходит *внутри* самого меню жанров (`e.target.closest('ul[role="listbox"]')` и `[data-baseweb="menu"]`), функция закрытия игнорируется.
2. **CSS свойство `overflow`**: В стилях `[data-baseweb="menu"]` было жестко задано `overflow: hidden !important;`, что физически уничтожало ползунок прокрутки для длинных списков и вызывало баги. Заменено на `overflow-y: auto !important; overflow-x: hidden !important;`, чтобы вернуть браузерный скроллинг внутрь выпадающих списков.

Теперь длинный список жанров можно смело листать колесиком или тапом без внезапного закрытия!

## 24.02.2026 (вт, Update 34)
### 🐛 Bug Fix: Предупреждение `st.radio` (theme_radio)
**Статус**: Выполнено

#### Постановка задачи
Появилось предупреждение Streamlit: `The widget with key "theme_radio" was created with a default value but also had its value set via the Session State API.` Это происходит, когда мы пытаемся установить `index=` в виджете `st.radio`, в то время как значение этого счетчика/виджета уже существует в словаре `st.session_state` и мы пытаемся им манипулировать.

#### Решение

1. Виджет `st.radio` (Theme Switch) инициализируется один раз в `st.session_state` перед тем, как отрендериться, на основе флага `dark_mode`.
2. В сам `st.radio` передан коллбэк `on_change=update_theme`.
3. Функция `update_theme` напрямую запрашивает новое состояние у виджета из Session State и обновляет флаг `dark_mode`.
Теперь данные идут лишь в одну правильную сторону (состояние -> виджет -> вызов on_change -> обновление состояния), предупреждение больше не генерируется.

## 23.02.2026 (пн, Update 30)
### 🎙️ Core Logic: Истинная синхронизация "Караоке" через WebVTT/Таймкоды
**Статус**: Выполнено

#### Постановка задачи
Пропорциональный расчет задержек караоке (на основе процентов от длительности трека) приводил к плавному рассинхрону к концу сказки. Пользователь запросил, чтобы скрипт "слушал" аудио и синхронизировал текст со словами диктора с абсолютной точностью.

#### Решение
Для реализации настоящего синхронного выделения текст был переведен с математических предположений (пропорций) на точные таймкоды от Text-to-Speech энкодера:
1. **Бэкенд (`generate_audio_stream`)**: Функция генерации аудио дополнена сканированием `WordBoundary` (границ слов), которые отдаёт `edge-tts`. Теперь функция опционально может возвращать не только байт-код аудио, но и массив JSON-объектов `word_boundaries` с точными полями `text`, `offset` (начало слова) и `duration` (его продолжительность).
2. **Фронтенд (`display_audio_player`)**: 
   - Объекты `word_boundaries` прокидываются на фронт. JavaScript-драйвер караоке переписан с использования процентов на поиск "текущего слова" по времени: проверяется условие `currentTime >= offset` && `currentTime <= offset + duration`.
   - Внедрена система fallback'а для старых аудиозаписей, у которых нет кэшированных таймкодов (останется старая пропорциональная логика с экспоненциальным сглаживанием).
   - Для устранения миллисекундного ощущения "тяжести" при чтении была внедрена компенсация задержки браузера `syncLookahead = 0.50` (500 миллисекунд), благодаря которой цвет зажигается ровно в момент произнесения звука.
3. **Реорганизация UI Плеера**:
   - Убрано дублирующееся системное уведомление "🎧 Плеер (MP3 можно скачать в плеере)".
   - **Идеальный Floating Player**: Компонент плеера теперь динамически вынимается из потока (`position: fixed; bottom: 15px;`) и абсолютно всегда находится поверх всех кнопок на самом дне браузера. С помощью ResizeObserver ширина плеера жестко привязана к ширине колонки сказки (учитывает открытие/закрытие сайдбара).
   - Устранены все белые подложки и дублирующиеся тени от iframe Streamlit.
   - **Исправление контролов**: Переписан JavaScript для ползунка прогресса и громкости. Внедрены блокировки автоматического обновления `ontimeupdate` при `mousedown`/`touchstart`.

### 🐛 Исправление мерцающего alert при загрузке страницы
**Статус**: Выполнено

#### Проблема
При загрузке страницы внизу на мгновение появлялось красное мерцающее уведомление (alert), которое исчезало до того, как можно было прочитать текст.

#### Диагностика
1. Добавлено диагностическое логирование в `app.py` для проверки `st.secrets` — ключ загружается успешно
2. Добавлен JavaScript для перехвата alert'ов — не сработал, так как элемент появляется до загрузки скрипта
3. **Ключевой тест**: CSS `display: none` для `[data-testid="stAlert"]` — мерцание исчезло
4. Выявлено: проблема в CSS-анимации `alertFadeIn` в `styles.py:82-89`

#### Причина
CSS-анимация `alertFadeIn` применялась ко всем `[data-testid="stAlert"]` элементам. Streamlit при загрузке кратковременно создаёт "призрачный" alert-элемент (пустой или системный), который тут же удаляется. Анимация начиналась, но элемент исчезал до её завершения — создавая эффект мерцания.

#### Решение
**styles.py:81-91** — заменена анимация `alertFadeIn` на отложенное появление:
```css
[data-testid="stAlert"] {
    opacity: 0;
    animation: showAlertAfterDelay 0s forwards;
    animation-delay: 2s;
}

@keyframes showAlertAfterDelay {
    to { opacity: 1; }
}
```

Теперь alert'ы появляются только через 2 секунды после создания, что исключает мерцание от кратковременных элементов.

#### Изменённые файлы
- `styles.py`: изменена анимация для `[data-testid="stAlert"]`
- `app.py`: удалён диагностический код

- Остальные элементы sidebar всё равно получают правильный цвет через более специфичные правила
