## 18.02.2026 (ср, Update 20)
### 📦 Feature: Мультиформатный экспорт сказок
**Статус**: Выполнено

#### Задача
Реализовать скачивание сказки в форматах для электронных книг и устройств.

#### Реализация
**Новый модуль `export.py`** (~300 строк):
- `generate_txt()` — UTF-8 текст, универсальный
- `generate_pdf()` — через `fpdf2` с умным поиском Unicode-шрифта (Arial Windows → DejaVu Linux)
- `generate_epub()` — через `ebooklib`, EPUB3 с CSS-стилями (Kindle, Kobo, PocketBook, Apple Books)
- `generate_fb2()` — FictionBook2 через `xml.etree.ElementTree` без внешних зависимостей (PocketBook, FBReader, Bookmate)
- `generate_html()` — красивый адаптивный HTML с градиентным фоном и типографикой

**Архитектурные решения:**
- Каждый генератор — чистая функция `(title, body, lang) → bytes`, легко тестируется
- Кэширование в `st.session_state[f"export_cache_{fmt}"]` — файл генерируется один раз
- Автосброс кэша при генерации новой сказки
- Поддержка всех 8 языков интерфейса (подписи, метаданные)
- Markdown-разметка (`**bold**`) корректно обрабатывается в каждом формате

**Изменения в `app.py`:**
- Заменена одна кнопка TXT на `st.selectbox` + `st.download_button` с выбором формата
- Импорт `EXPORT_FORMATS, get_export_data` из нового модуля

**Зависимости** (добавлены в `requirements.txt`):
- `fpdf2>=2.7.0` — PDF генерация
- `ebooklib>=0.18` — EPUB генерация

**Тест**: все 5 форматов прошли проверку (TXT 437b, PDF 36KB, EPUB 3KB, FB2 1.2KB, HTML 2.3KB)

**MOBI** намеренно исключён — требует внешних инструментов (Calibre/KindleGen). Пользователи могут конвертировать EPUB → MOBI через Calibre бесплатно.

Кнопка «В библиотеку» была **нечитаема** в тёмной теме (белый фон, серый текст). Текст кнопок был частично захардкожен, без i18n.

#### Решение — Toolbar-панель
Реализован **Вариант 3 (Toolbar)**: все три кнопки в единой горизонтальной панели.

##### Изменения в `app.py` (строки 1168-1222):
- `st.download_button` + `st.columns([1,1,2])` → единый `st.columns(3, gap="small")`
- Ключи кнопок: `toolbar_download`, `toolbar_voice`, `toolbar_save`
- Все тексты через i18n-словари (8 языков)
- `use_container_width=True` для одинаковой ширины
- `type="primary"` убран с кнопки «Озвучить» для единообразия панели

##### Изменения в `styles.py` (~120 строк CSS):
- **Glassmorphism-контейнер**: `background: rgba(255,255,255,0.03)`, `border-radius: 16px`, `backdrop-filter: blur(10px)`
- **Вертикальные разделители** между колонками через `border-right`
- **Hover-эффекты**: `translateY(-1px)`, фиолетовый glow `rgba(102,126,234,0.12)` фон
- **Анимация processing**: `toolbar-pulse` — пульсирующая прозрачность
- **Active state**: `scale(0.97)` для тактильной обратной связи
- Все стили адаптивны: разные значения для dark/light тем

##### Фикс CSS-специфичности (унификация кнопок):
Глобальный secondary-стиль (`div.stButton:not([class*="st-key-del_"]) > button:not([kind="primary"])`, специфичность **0,3,2**) перебивал toolbar-стили, т.к. класс `st-key-toolbar_voice` находится на `div.stElementContainer` (родитель `div.stButton`), а не на самом `div.stButton`.

**Решение** — override с повышенной специфичностью **(0,3,3)**:
```css
div[class*="st-key-toolbar_"] div.stButton > button:not([kind="primary"]) {
    background: transparent !important;
    background-image: none !important;
}
```
Подтверждено через `getComputedStyle()`: `backgroundImage: "none"`. Все три кнопки теперь **идентичны**.

## 14.02.2026 (Утро, Update 2)
### 🐛 Исправление мерцающего alert при загрузке страницы
**Статус**: Выполнено

#### Проблема
При загрузке страницы внизу на мгновение появлялось красное мерцающее уведомление (alert), которое исчезало до того, как можно было прочитать текст.

#### Диагностика
1. Добавлено диагностическое логирование в `app.py` для проверки `st.secrets` — ключ загружается успешно
2. Добавлен JavaScript для перехвата alert'ов — не сработал, так как элемент появляется до загрузки скрипта
3. **Ключевой тест**: CSS `display: none` для `[data-testid="stAlert"]` — мерцание исчезло
4. Выявлено: проблема в CSS-анимации `alertFadeIn` в `styles.py:82-89`

#### Причина
CSS-анимация `alertFadeIn` применялась ко всем `[data-testid="stAlert"]` элементам. Streamlit при загрузке кратковременно создаёт "призрачный" alert-элемент (пустой или системный), который тут же удаляется. Анимация начиналась, но элемент исчезал до её завершения — создавая эффект мерцания.

#### Решение
**styles.py:81-91** — заменена анимация `alertFadeIn` на отложенное появление:
```css
[data-testid="stAlert"] {
    opacity: 0;
    animation: showAlertAfterDelay 0s forwards;
    animation-delay: 2s;
}

@keyframes showAlertAfterDelay {
    to { opacity: 1; }
}
```

Теперь alert'ы появляются только через 2 секунды после создания, что исключает мерцание от кратковременных элементов.

#### Изменённые файлы
- `styles.py`: изменена анимация для `[data-testid="stAlert"]`
- `app.py`: удалён диагностический код

#### Причина (Root Cause)
- **Misplaced `st.set_page_config`**: Команда настройки страницы была вызвана на 298-й строке `app.py`, после того как в сайдбаре или основном теле уже были выполнены другие команды Streamlit.

#### Решение
- Переместил `st.set_page_config` в самое начало файла `app.py` (сразу после импортов).
- Удален временный workaround с `st.empty().write("")`.
- Проведена чистка дублирующихся строк в коде кнопок озвучки.

## 13.02.2026 (Вечер, update 8)
### 🎯 UI: Финальное исправление цвета radio-кнопок через :not() селектор
**Статус**: Завершено

#### Прошлая проблема
- update 7 не сработало потому что универсальное правило `section[data-testid="stSidebar"] * { color: ... !important }` всё равно переопределяло inputs
- CSS каскад: последнее правило выигрывает, если они имеют одинаковую специфичность

#### Финальное решение
- Заменил универсальное правило на исключающее:
  ```css
  section[data-testid="stSidebar"] *:not(input[type="radio"]):not(input[type="checkbox"]) {
      color: (текст) !important;
  }
  ```
- Теперь inputs НЕ попадают под это правило и сохраняют свои цвета
- Все остальные элементы (label, p, span) по-прежнему получают нужный цвет текста

#### Почему это работает
- `:not()` селектор исключает matching элементов из правила
- Используются два `:not()` для исключения both типов inputs
- Остальные элементы sidebar всё равно получают правильный цвет через более специфичные правила

#### Результат
- ✅ Radio кнопки теперь белые/видимые (благодаря accent-color выше)

- ✅ Никаких конфликтов в CSS каскаде
